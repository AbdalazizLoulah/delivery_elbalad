# ديليفاري البلد 🛵

تطبيق توصيل متكامل في مصر بثلاث أدوار — **مشتري** و**بائع** و**دليفاري** —
مبني بـ Flutter بمعمارية نظيفة (Clean Architecture) و BLoC و SOLID مع حقن
الاعتماديات (DI).

## المميزات

- **ثلاث تسجيلات دخول مستقلة**: كل دور له حساب ولوحة تحكم خاصة بيه.
- **خرايط OpenStreetMap**: تحديد عنوان التوصيل وموقع المتجر بالسحب على الخريطة،
  مع تحويل الإحداثيات لعنوان مكتوب (بدون مفتاح API أو بطاقة بنكية).
- **تتبع مباشر للطلب**: المشتري بيتابع الطيار على الخريطة لحظة بلحظة مع المسافة
  المتبقية بالطريق وزمن الوصول المتوقع لحد ما الطلب يوصل.
- **أقرب طيار**: الطلب الجاهز بيتعرض تلقائيًا على أقرب طيار متاح، ولو رفضه
  بيتحوّل للي بعده.
- **تقييم الطيار**: بعد التسليم المشتري بيقيّم الطيار بالنجوم.
- **إلغاء من الطيار**: الطيار يقدر يلغي الطلب **بس لو الدفع عند الاستلام**؛ الطلبات
  المدفوعة أونلاين مينفعش تتلغى من الطيار (بعد تأكيد بوب-أب).
- **دفع مرن**: فيزا أو كاش عند الاستلام، مع حساب مصاريف الدليفاري تلقائيًا
  (قيمة ثابتة + سعر لكل كيلومتر).
- **سلة ومفضلة لكل مستخدم** محفوظين محليًا وبيرجعوا لما يسجل دخول تاني.
- **الوضع التجريبي**: التطبيق شغال كامل من غير أي باك إند — بيانات وحسابات
  وطلبات جاهزة للتجربة.

## المتطلبات

- Flutter 3.47 أو أحدث (Dart 3.13+).
- Android Studio أو Xcode لو هتشغّل على موبايل/محاكي.

## تشغيل سريع (الوضع التجريبي)

```bash
flutter pub get

```

من غير أي إعدادات، التطبيق بيشتغل بالبيانات التجريبية المحلية. هتلاقي بيانات
الحسابات معروضة جوه شاشة اختيار الدور وفي تاب "حسابي":

| الدور | البريد الإلكتروني | كلمة السر |
| --- | --- | --- |
| مشتري | `buyer@elbalad.app` | `123456` |
| بائع | `seller@elbalad.app` | `123456` |
| بائع تاني | `seller2@elbalad.app` | `123456` |
| دليفاري | `courier@elbalad.app` | `123456` |
| دليفاري تاني | `courier2@elbalad.app` | `123456` |

### سيناريو مقترح للتجربة

1. سجّل دخول **مشتري**: اتفرج على المتجر، ضيف للسلة، واطلب بعنوان ودفع
   (فيزا أو كاش)، وتابع الطلب من "طلباتي".
2. سجّل دخول **بائع**: من "لوحة المتجر" جهّز الطلب الجديد (تحت التنفيذ ← جاهز
   للاستلام) وبعدها التطبيق بيعرضه على أقرب طيار تلقائيًا.
3. سجّل دخول **دليفاري**: هتلاقي طلب معروض عليك لأنك الأقرب (أو طلبات قريبة
   منك) — اقبله، استلمه من المتجر، ووصّله للعميل.
4. ارجع للـ **مشتري** وتابع الخريطة وقيّم الطيار بعد التسليم.

## توصيل الباك إند الحقيقي (Supabase)

1. اعمل مشروع جديد على [supabase.com](https://supabase.com).
2. من **SQL Editor** شغّل محتوى الملف `supabase/schema.sql` — بينشئ كل الجداول
   (profiles / categories / products / addresses / orders / order_items /
   order_events / courier_locations) مع سياسات RLS وجداول الـ Realtime وتريجر
   إنشاء الملف الشخصي عند التسجيل وتصنيفات البداية، وكمان bucket تخزين صور
   المنتجات (`product-images`) على Supabase Storage مع سياسات الرفع.
3. مفاتيح المشروع مضمّنة كقيم افتراضية في `lib/core/config/app_config.dart`،
   فالتطبيق بيتصل بـ Supabase تلقائيًا مع أي بناء عادي (`flutter run` أو
   `flutter build apk`) من غير إعدادات زيادة.
4. لو حبيت تجرّب مشروع تاني أو تغيّر المفاتيح، غيّرها وقت البناء (القالب في
   `config/config.example.json`):

```bash
flutter build apk --release --dart-define-from-file=config/dev.json
```

> **ملحوظة**: لو خيار "Confirm email" مفعّل في مشروع Supabase
> (Authentication ← Sign In / Providers ← Email)، لازم تأكّد الإيميل قبل أول
> دخول؛ أو اقفل الخيار دا للتجربة السريعة.
>
> لو `SUPABASE_URL` و `SUPABASE_ANON_KEY` فاضيين، التطبيق بيرجع تلقائيًا
> للوضع التجريبي المحلي. ملف `config/dev.json` متجاهَل في git.

### متغيرات الإعداد

| المتغير | الاستخدام |
| --- | --- |
| `SUPABASE_URL` | رابط مشروع Supabase |
| `SUPABASE_ANON_KEY` | المفتاح العام (anon / publishable) |
| `GOOGLE_MAPS_API_KEY` | غير مستخدم حاليًا (الخرائط بقت OpenStreetMap) |

## الخرائط والمسافات

- الخرائط بقت **OpenStreetMap** عن طريق `flutter_map` — مجانية وبدون مفتاح API.
- كل الخرائط بتفتح **جوّه التطبيق** (فيه زرار "فتح الخريطة كاملة" بيفتح شاشة كاملة).
- المسافة المتبقية بين الطيار والعميل بتتحسب من **OSRM** (مسافة الطريق الحقيقي + زمن
  الوصول المتوقع) وبتظهر كشارة على الخريطة، وفي حال تعذّر الوصول للخدمة بيرجع
  تلقائيًا للمسافة المباشرة (Haversine) ويظهر "خط مباشر (تقديري)".
- تحديث موقع الطيار كل 10 ثواني، وتحديث المسافة على خريطة العميل كل 8 ثواني كاحتياطي
  بجانب Realtime.

## حل المشاكل الشائعة

| المشكلة | السبب | الحل |
| --- | --- | --- |
| شاشة إضافة المنتج واقفة على "بنجيب التصنيفات..." | جدول `categories` مش موجود على Supabase | شغّل `supabase/schema.sql` من SQL Editor ثم اضغط "حاول تاني" |
| رفع الصورة بيفشل ويقول `Bucket not found` | bucket اسمه `product-images` مش متعمل | نفس الحل: السكيما بتنشئ الـ bucket وسياسات الرفع |
| `permission denied for table profiles` | الجدول اتعمل من غير منح الصلاحيات (grants) | نفس الحل: السكيما بتمنح الصلاحيات للـ anon/authenticated |
| المنتج بيتحفظ لكن مش بيظهر في السوق | المنتج مربوط بتاجر مش دوره `seller` | صحّح الدور: `update public.profiles set role = 'seller' where email = '...';` |
| رسالة `email rate limit exceeded` عند التسجيل | محاولات تسجيل كتير في وقت قصير | استنى شوية، أو اقفل "Confirm email" من إعدادات Authentication |

> بعد تشغيل السكيما لأول مرة، اعمل Refresh لشاشة التصنيفات أو أعد فتح الصفحة.

## بنية المشروع

```
lib/
  core/                الإعدادات، الأخطاء، Result، الثيم، الراوتر، DI،
                       خدمات الموقع، الودجتس المشتركة، قاعدة البيانات التجريبية
  features/
    auth/ buyer/ cart/ catalog/ checkout/ delivery/ favorites/ orders/
    profile/ seller/
      domain/          كيانات + عقود المستودعات + حالات الاستخدام
      data/            مصادر بيانات (Supabase + محلي) + تنفيذ المستودعات
      presentation/    بلوكات (BLoC) + شاشات + ودجتس
supabase/schema.sql    سكيما الباك إند كاملة
config/                نموذج ملف الإعدادات المحلي
test/                  اختبارات الوحدة ورحلة التطبيق الكاملة
```

أهم المبادئ المتبعة:

- **Result\<T\> + AppFailure** بدل الاستثناءات في كل الطبقات.
- **مصدرين بيانات بنفس العقود**: Supabase للإنتاج و DemoDatabase للتجربة،
  والتبديل تلقائي حسب وجود المفاتيح.
- **فصل العقود (ISP)**: مستودعات منفصلة للمشتري والبائع والدليفاري فوق مصدر
  بيانات واحد.
- **get_it** لحقن الاعتماديات — الواجهة بتتعامل مع البلوكات وخلاص.

## إدارة المستخدمين حسب الدور

الدور بيتخزن في عمود `role` جوه جدول `profiles`، وليه 3 قيم:

| الدور | القيمة | الصلاحيات |
| --- | --- | --- |
| عميل | `buyer` | يتفرج ويشتري ويعمل طلبات |
| تاجر | `seller` | يدير منتجاته ويرد على طلبات الشراء |
| دليفاري | `courier` | يستلم التوصيل ويحدّث موقعه |

### إزاي تجيب كل التجار أو كل الدليفاري (SQL Editor)

```sql
-- كل التجار
select id, full_name, email, phone, created_at
from public.profiles
where role = 'seller'
order by created_at desc;

-- كل الدليفاري
select id, full_name, email, phone, is_available
from public.profiles
where role = 'courier'
order by created_at desc;

-- كل العملاء
select id, full_name, email, phone
from public.profiles
where role = 'buyer'
order by created_at desc;

-- تغيير دور حساب معين (بعدها المستخدم يعمل خروج ودخول)
update public.profiles set role = 'seller' where email = 'someone@gmail.com';
```

### من كود Flutter

```dart
final supabase = Supabase.instance.client;

final sellers = await supabase.from('profiles').select().eq('role', 'seller');
final couriers = await supabase.from('profiles').select().eq('role', 'courier');
final buyers = await supabase.from('profiles').select().eq('role', 'buyer');
```

### من لوحة Supabase

Table Editor ← جدول `profiles` ← Filter ← `role = seller`.

> الصلاحيات محمية على مستوى قاعدة البيانات (RLS): التاجر بس اللي يقدر يضيف
> منتجات أو يرفع صور، والدليفاري بس اللي يحدّث موقعه، والعميل بس اللي ينشئ
> طلبات. وتغيير دور أي حساب بيتم من لوحة Supabase أو SQL Editor فقط.
